# Documentation guidance

Sources checked 2026-09-07. Recheck for claims about current platform behavior.

- [GitHub: About READMEs](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-readmes)
  recommends explaining what a project does, why it is useful, how to start,
  where to get help, and who maintains it. Use headings and relative links to
  keep the entry point navigable and connected to detailed documentation.
- [AGENTS.md](https://agents.md/) describes a dedicated location for coding-agent
  setup, tests, and conventions that complements the human-facing README.
  Apply this by linking a shared installation guide and keeping contributor
  operations in AGENTS.md; do not duplicate the whole README there.
- [GitHub: Repository topics](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/classifying-your-repository-with-topics)
  explains topic-based discovery. Choose terms describing the actual purpose
  and subject. The documentation does not establish that a specific rename or
  keyword produces higher ranking or more users.

Editorial recommendation: problem → approach → useful output → first result.
This order expresses the user's documentation preference and an adoption task;
it is not a controlled finding about README conversion. Test it with real readers
if claiming comprehension or adoption improvements.
